# P2 清洗与匹配规则

> 本文档是**规则文档**，定义"以后处理P2原始文件时要遵守什么规则"，本身不处理任何数据。
> 真正开始清洗前，我会先扫描你提供的原始文件（采购、入库、库存、发票），输出一份"数据概况报告"
> （有哪些文件/Sheet/字段、大概多少行、初步发现哪些问题），等你确认后才会正式按下面的规则清洗——
> 不会没打招呼就先把8月发票校验总表.xlsx、7月发票PDF这些已经出现在项目目录里的新文件处理掉。

## 一、必须识别的问题清单

清洗时会逐项排查以下13类问题，每发现一类都会在"数据概况报告"里列出具体条数和样例，而不是先斩后奏改完再告诉你：

1. 同一采购单跨多行或多Sheet（比如同一天同一供应商的单子被拆在了两个Sheet或两个文件里）
2. 同一供应商名称存在格式差异（沿用P1已经建立的"供应商"表做匹配，不重新发明一套判断逻辑）
3. 物料名称与P1主数据不完全一致（新单据里的写法和P1清洗后的"标准物料名称"对不上）
4. 同一物料存在不同计量单位（比如同一个SKU，有的单据按"箱"下单，有的按"包"验收）
5. 箱、件、袋、瓶、公斤、斤等单位换算缺失（P1阶段这个字段大多是空的，需要靠实际单据数据反推或人工补）
6. 采购数量与入库数量不一致
7. 入库金额与发票金额不一致
8. 一张发票关联多个入库单
9. 多张发票关联一个采购单
10. 缺少采购单号或入库单号（原始记录里没有编号，需要靠日期+供应商+金额等信息去重新识别归属）
11. 日期格式异常（比如中澳日期格式混用 DD/MM vs MM/DD，或Excel把日期存成了文本）
12. 金额、税额或数量错位（列对不齐，比如GST写到了金额列）
13. 内部入库被误识别为外部采购（总仓配送/店内自制被当成了向供应商采购）
14. 同名物料实际为不同规格（比如都叫"辣椒油"，但一个是1L桶装一个是200ml小瓶装，成本口径不同）
15. 同一单据被重复导入（同一张发票/入库单因为文件重复上传或多个来源重复统计而被算了两次）

> 这份清单参考了P1阶段实际遇到的问题类型（P1里已经出现过"供应商字段疑似错位"“同名物料同时是自制品和采购品”这类情况），P2大概率会遇到类似甚至更多问题，所以列得比较全，实际扫描后可能会追加。

## 二、匹配优先级

### 2.1 物料匹配（新单据里的一行 → 对应P1哪个SKU）

按顺序尝试，**一旦某一级匹配成功就停止，不再往下试更弱的匹配方式**：

1. **SKU 精确匹配**：如果原始单据本身就带有SKU（比如飞书里录入时手动选过），直接用，最高优先级
2. **标准物料名称 + 规格 精确匹配**：与P1"物料主数据"表里的"物料名称"+"规格"逐字完全一致
3. **原始物料名称映射匹配**：与P1"物料主数据"表里的"原始物料名称"逐字完全一致（同一种写法在不同单据里重复出现是最常见情况）
4. **供应商 + 物料名称 + 单位 联合匹配**：三者都对得上，才认为是同一物料（避免不同供应商用同一个名字卖不同东西）
5. **模糊匹配**：字符相似度高但不完全一致——**只生成建议，写入"采购单物料匹配_待确认"表，绝不直接写入正式的采购单明细表**
6. 以上全部失败：进入"采购单物料匹配_待确认"表，标记"无法确定"，人工从头指定

### 2.2 供应商匹配（新单据里的供应商 → 对应P1哪个供应商记录）

1. **供应商ID 精确匹配**
2. **标准供应商名称 精确匹配**（P1"供应商"表的"供应商名称"字段）
3. **原始名称映射匹配**（P1"供应商"表的"原始名称"字段里任一别名精确匹配）
4. **税号（ABN）或银行信息匹配**：如果发票上有ABN，且和供应商表里已登记的ABN一致
5. **模糊名称匹配**：**只生成建议，写入"采购单供应商匹配_待确认"表，绝不直接写入正式表**

### 2.3 强制原则

- **任何一级如果不是"精确匹配"，一律不直接更新正式数据表**——这是从P1延续下来的硬规则，P2同样适用，不因为是新模块就放松。
- 精确匹配成功但结果与常识明显矛盾的（比如金额是负数且没有标注"退货"、数量为0但金额不为0），依然要落入待确认表，不能因为"字符串匹配上了"就认为数据一定对。
- 无法判断的数据**不会被丢弃**：所有类型不明、无法识别的原始行，都会连同原始文件名、Sheet名、行号一起保留在对应的"待确认"表或"异常"表里（沿用P1"供应商字段异常_物料清单"的做法），不会因为处理不了就悄悄跳过。

## 三、扫描阶段的输出物（正式清洗开始前）

等你说"可以扫描了"、并指明要扫描哪些具体文件（比如8月发票校验总表.xlsx、7月的几个发票PDF、还是你会另外上传新的采购/入库/库存文件），会先输出：

1. **文件与Sheet清单**：每个文件有哪些Sheet、大概多少行、看起来是什么类型的数据（采购/发票/入库/库存）
2. **字段映射表**：每个原始字段大致对应P2字段字典里的哪个字段，哪些字段找不到对应、需要新增
3. **问题预估**：对照上面"必须识别的问题清单"，粗略估计每类问题大概有多少条
4. **风险点**：比如PDF发票需要走OCR/人工誊录，样本量、准确率预期等

拿到这份报告、你确认范围和优先级之后，才会正式按本文档的规则做清洗和匹配，输出结果同样会是"正式表 + 待确认表 + 数据质量报告"这一整套，和P1的产出形态一致。
