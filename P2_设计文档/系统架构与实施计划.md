# 系统架构与实施计划

## 一、飞书与定制网页的数据同步边界

最终形态：**定制网页系统（正式数据库） + 飞书多维表（入口/协作/移动端）**，飞书不作为唯一数据库。

| 能力 | 定制网页负责 | 飞书负责 |
|---|---|---|
| 数据存储 | ✅ 唯一权威数据源（独立数据库） | ❌ 不作为唯一权威源，是同步出来的一份"可协作副本" |
| 全局检索 | ✅ | 有限（飞书自带搜索/筛选，够日常用但不做全局跨表检索） |
| 采购/入库/发票/附件详情页 | ✅ 完整详情页 + 单据互相跳转 | 简单记录查看，复杂跳转关系不在飞书里实现 |
| 文件/图片/PDF 上传与预览 | ✅ 正式存储与预览 | 可以上传，但作为"网页系统"的镜像/入口，非最终存档位置 |
| 复杂关联查询（按日期+供应商一次看全部单据） | ✅ | ❌ 飞书多维表的关联查询能力有限，做不到这种跨6-7张表的聚合视图 |
| 叫货/消耗趋势图 | ✅ | ❌（飞书仪表盘只能做简单图表，做不了"叫货曲线 vs 消耗曲线"这种双指标趋势对比） |
| 库存流水明细 | ✅ 完整明细+汇总 | 可以看简单汇总，不做流水级别的复杂钻取 |
| 单据一键跳转 | ✅ | ❌ 飞书原生关联字段能点开，但做不到"从一张发票一键跳转到关联的入库单+采购单+库存流水"这种多级联动 |
| 权限控制 | ✅ 精细到字段/操作级别 | 飞书自带的表格/记录级权限，作为补充 |
| 操作日志 | ✅ 系统级完整审计 | 飞书自带修改记录，作为补充参考 |
| 入口/消息通知 | 可选（也可以只靠飞书通知） | ✅ 飞书机器人/群消息 |
| 待办与审批 | 可对接飞书审批流 | ✅ 飞书审批/任务 |
| 移动端访问 | 响应式网页（后续可做） | ✅ 飞书App天然支持 |
| 异常提醒（缺货/超支/临期） | 网页系统计算，结果推送 | ✅ 作为提醒触达渠道 |
| 简单数据维护（改个电话号码这种） | ✅ | ✅ 均可，飞书更适合非技术同事随手改 |

### 数据怎么同步

- 权威方向：**网页系统数据库 → 飞书**（单向为主）。业务逻辑判断、复杂计算、匹配规则都在网页系统后端跑，跑完的结果同步一份到飞书多维表供查看和协作。
- 少量"简单维护"字段（比如供应商电话、备注）允许反向从飞书同步回网页系统数据库，但这类字段要明确列白名单，不是所有字段都双向同步，避免冲突。
- P1/P2现阶段（还没有网页系统）：飞书多维表本身**暂时充当**唯一的数据存放地，Excel（这几份 `_导入包`/`_最终版`/`_人工确认与回填包`）是"导入飞书之前的加工车间"。等网页系统开发排上日程后，会把飞书多维表的角色切换成"网页数据库的协作视图"，导入方式也会从"Excel导入"切换成"API/MCP双向同步"。

## 四、验收要求核对表

| 要求 | 当前状态（P1） | 说明 |
|---|---|---|
| 所有表都有永久唯一ID | ✅ | SKU / 供应商ID |
| SKU 永久稳定 | ✅ | 一次性生成，规则和承诺写在《P1_飞书建表操作步骤.md》第三节 |
| 原始字段全部保留 | ✅ | 原始物料名称/原始供应商文本/原始名称/数据来源明细，全程不覆盖 |
| 正式值与原始值分开 | ✅ | 每张表原始字段与清洗后字段是不同列 |
| 自动建议与人工确认分开 | ✅ | 置信度/待确认列 + 独立的"待确认"sheet + 回填包的红/黄/绿/灰配色 |
| 无法判断的数据不允许静默丢弃 | ✅ | 待分类/无供应商/疑似重复/冲突/异常，全部落表，回填脚本的冲突也全部落"本次冲突未写入" |
| 所有变更可追溯 | ✅ | 累计变更日志(change_log.csv + 最终版.xlsx里的"累计变更日志"sheet) |
| 重复导入不会产生重复记录 | ✅ | 回填脚本已用重复运行测试验证（见下） |
| 采购、入库、发票和附件可以互相追踪 | ⬜ P2待建 | 本文档ER关系已设计，尚未落地数据 |
| 数据结构支持按日期、供应商、物料查询 | ⬜ P2待建 | 字段字典已覆盖，尚未落地数据 |
| 数据结构支持叫货曲线和消耗曲线 | ⬜ P2待建 | 已在库存流水表设计中明确"叫货数量"与"消耗数量"分离存储 |

**关于"重复导入不会产生重复记录"和"变更可追溯"的验证**：这次实际测试了P1回填脚本——填入测试确认数据后运行，正常变更被记录、无效数据被正确挡在冲突表里没有写入正式表；不改任何输入重新运行第二次，变更条数归零（全部识别为"已是最新状态"）、累计日志条数没有翻倍；并且专门构造了一个"这次的合并决定和上次矛盾"的场景，脚本也正确识别并拒绝写入，而不是覆盖历史决定。这套机制后续会原样复用到P2的回填脚本上。
